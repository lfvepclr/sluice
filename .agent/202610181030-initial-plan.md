## 1. 目标与边界

**目标**

1. 隧道模式：本地端口 → 公网地址，随机子域名（可自定义）。
2. 转发模式：本地 `127.0.0.1:1234`，请求路径带完整目标 URL，经隧道转发。
3. 自研代码 `#![forbid(unsafe_code)]`。
4. 用户配置极简，默认值即性能最优值。
5. 单二进制、静态链接、OpenRC 托管。

**非目标**

多租户与用户体系、Web 管理后台、UDP / 任意 TCP 隧道、流量计费、集群调度。

## 3. 软件架构

### 3.1 分层视图

```
┌───────────────────────────────────────────────────────────────┐
│ L1 接入层  ingress                                            │
│   :80 (plain)  :8443 (TLS)  :7835 (control, TLS + SPKI pin)   │
│   hyper HTTP/1.1 编解码 · Host/SNI 路由 · 限流                 │
├───────────────────────────────────────────────────────────────┤
│ L2 会话层  session                                            │
│   Hello 握手 · token 校验 · 会话表 · 子域名分配 · 心跳/保留期   │
├───────────────────────────────────────────────────────────────┤
│ L3 复用层  mux                                                │
│   yamux 连接 · 双向开流 · 每流一个 HTTP 请求 · 流控/背压        │
├───────────────────────────────────────────────────────────────┤
│ L4 转发层  forwarding                                         │
│   expose: 请求灌入本地端口   forward: path 解析 + 出口发起      │
├───────────────────────────────────────────────────────────────┤
│ L5 基础层  infra                                              │
│   config · logging · tls/acme · metrics · error · net helpers  │
└───────────────────────────────────────────────────────────────┘
```

依赖方向严格自上而下；L4 不依赖 L1 的具体监听器，L3 不感知 HTTP 语义。

### 3.2 模块职责

| 模块 | 职责 | 对外接口 | 禁止事项 |
| --- | --- | --- | --- |
| `server::ingress` | 监听 80/8443，解析 Host，路由到会话 | `serve(listeners, registry)` | 不做协议解析以外的事 |
| `server::control` | 7835 握手、会话注册、子域名分配 | `accept_loop(registry)` | 不碰 HTTP 流量 |
| `server::tunnel` | 每请求开流并写 HTTP | `proxy(session, req)` | 不缓冲 body |
| `server::egress` | forward 模式出网 | `fetch(target, req)` | 不跟随重定向 |
| `server::tls` / `acme` | 证书存储与签发 | `CertStore::current()` | 不阻塞请求路径 |
| `agent::expose` | 承接流 → 本地端口 | `serve_stream(stream)` | 不改写 body |
| `agent::forward` | 本地代理 → 双出口 | `handle(req, egress)` | 不缓存响应 |
| `common::*` | 纯函数：解析/判定/生成 | 无 IO | 不做 IO |

### 3.3 核心抽象

```rust
/// 会话注册表：子域名 → 会话句柄
pub struct SessionRegistry { map: DashMap<String, Session> }

pub struct Session {
    subdomain: String,
    mode: Mode,                 // Expose | Forward
    ctrl: yamux::Control,       // 用于开流
    last_seen: AtomicU64,
}

pub enum Mode { Expose, Forward }

/// 出口抽象：本地直连与经服务器共用同一套上层逻辑
#[async_trait]
pub trait Egress: Send + Sync {
    async fn fetch(&self, target: Target, req: Request<Incoming>) -> Result<Response<BoxBody>>;
}

/// 证书存储：热替换不重建 ServerConfig
pub struct CertStore { current: ArcSwap<CertifiedKey> }
impl ResolvesServerCert for CertStore { /* 读 ArcSwap，同步返回 */ }

/// DNS 挑战提供者：换域名/换服务商只加实现
#[async_trait]
pub trait DnsProvider: Send + Sync {
    async fn set_txt(&self, fqdn: &str, value: &str) -> Result<()>;
    async fn clear_txt(&self, fqdn: &str) -> Result<()>;
}
```

### 3.4 运行时拓扑（单核约束）

| Task | 数量 | 生命周期 |
| --- | --- | --- |
| listener accept（80 / 8443 / 7835） | 3 | 进程级 |
| 入站连接处理 | 每连接 1 | 连接级 |
| 单请求流处理 | 每请求 1 | 请求级，短命 |
| 会话控制循环 | 每会话 1 | 会话级 |
| 心跳/超时巡检 | 1 | 进程级，1s tick |
| ACME 续期 | 1 | 进程级，12h tick |

- `tokio` 运行时 `worker_threads = 1`（单核，避免线程切换开销），`blocking` 线程池留给文件与 ACME 的同步操作。
- 每会话并发流上限 128，全局连接上限 512；超限直接 `503`，不排队（3 Mbps 下排队只会放大延迟）。
- 所有 task 由 `JoinSet` 管理，退出时统一 drain。

### 3.5 请求生命周期

**expose**

```
accept(TCP) → TLS?(8443) → hyper serve_connection
  → 取 Host 首标签 → registry.lookup
      ├─ miss → 404
      └─ hit  → ctrl.open_stream()
                → 写 [kind=0][HTTP/1.1 head + body 流式]
                → agent: serve_connection(stream) → connect 127.0.0.1:port
                → 响应字节流回灌 → 客户端
```

**forward（server 出口）**

```
accept(127.0.0.1:1234) → hyper serve_connection
  → parse_target(path) → Target{scheme,host,path,query}
  → ctrl.open_stream() → 写 [kind=1][meta][HTTP/1.1]
  → server: serve_connection(stream) → SSRF 校验 + pin IP
            → reqwest 出网 → 响应流回灌
```

**forward（local 出口）**：同上去掉开流，直接 `reqwest`。

### 3.6 状态机

```
Session:   Dialing → Handshaking → Active → Draining → Closed
               └── 失败 ──→ Backoff(1s,2s,4s…30s,±20%) ──→ Dialing

Subdomain: Free → Assigned → Reserved(60s) → Released → Free
                                └─ 同 token 重连 ─→ Assigned

Connection: Plain → TLS → Mux → Ready → (心跳丢失 45s) → Closed
```

### 3.7 错误处理

| 类别 | 表现 | 处理 |
| --- | --- | --- |
| 配置错误 | 启动即失败 | 打印具体字段与期望值，退出码 2 |
| 会话握手失败 | `Error` 帧 | 不重试（token/版本问题重试无意义），打印原因退出 |
| 单流失败 | 单请求 5xx | 关闭该流，会话保持 |
| 会话断开 | 所有流中断 | 退避重连，子域名保留 60s |
| 上游超时 | 504 | 不重试（避免放大） |
| 进程 panic | 进程退出 | `panic=abort`，OpenRC `supervise-daemon` 5s 后拉起 |

原则：**单流错误不污染会话，会话错误不拖垮进程，进程错误交给 OpenRC**。

### 3.8 配置设计（极简优先）

**服务端最少 3 项**，其余全默认：

```toml
base_domain = "xxx.duckdns.org"
token       = "…"
dns_token   = "…"
```

**客户端最少 1 项**：

```bash
sluice expose 8080 --server "$SLUICE_HOST"   # token 首次交互输入并缓存
sluice forward --server "$SLUICE_HOST"
```

优先级：`CLI 参数 > 环境变量（SLUICE_TOKEN / SLUICE_SERVER）> ~/.config/sluice/config.toml > 内置默认值`。

**原则**：不暴露调参项。缓冲区大小、流控窗口、超时、连接池全部内置为最优值——用户能调的参数越多，越容易把性能调坏。仅保留三个有语义的开关：`--egress`、`--subdomain`、`--tls`。

### 3.9 性能设计要点

| 层面 | 措施 |
| --- | --- |
| 内存拷贝 | 全程 `Bytes` / `Buf`；响应体 `Body::wrap_stream` 直接透传，**禁止 `collect()`** |
| 缓冲 | 固定 16 KB 读写块（BDP ≈ 14 KB，大缓冲只会加剧 bufferbloat） |
| TCP | 所有 socket `TCP_NODELAY=1`；`SO_SNDBUF/RCVBUF` 保持系统默认，不放大 |
| 复用 | yamux `receive_window=256KB`、`max_num_streams=128`、`split_send_size=16KB` |
| 连接池 | reqwest `pool_max_idle_per_host=16`、`pool_idle_timeout=90s` |
| 调度 | `worker_threads=1`，避免单核上下文切换 |
| 编译 | `opt-level=3`、`lto="fat"`、`codegen-units=1`、`panic="abort"`、`strip=true` |
| 压缩 | 默认关。3 Mbps 链路下文本压缩有收益但吃单核 CPU，留作 M9 后按数据决定 |

**验收**：`openssl s_client -servername <sub>.<base>` 校验 SAN 通过；私钥文件 `0600`；手动缩短有效期后能触发续期且不重启；`--tls self-signed` 可离线跑通全链路。

## 7. 构建与部署

### 7.1 本机构建（唯一路径）

`ring` 含 C 与汇编，无法用 `rust-lld` 单独完成 musl 交叉链接，因此**只有 sluice 这个仓库需要 zig**：

```bash
brew install zig
cargo install cargo-zigbuild
./scripts/build-musl.sh        # 内部：CC_x86_64_unknown_linux_musl="zig cc" cargo zigbuild --release --target x86_64-unknown-linux-musl
file target/x86_64-unknown-linux-musl/release/sluice   # 期望 statically linked
```

备选（不想装 zig）：把 TLS 加密后端换成纯 Rust 实现（`rustls-rustcrypto`），即可回到 Phantom 的 `rust-lld` 零 C 工具链路径。代价是该 provider 成熟度低于 ring，**涉及公网 TLS 服务端，默认不选**。

服务器只接收产物，不需要 Rust、编译器或任何构建依赖。

### 7.2 部署

```bash
scp sluice deploy/* "$SLUICE_HOST":/tmp/sluice-pkg/
ssh "$SLUICE_HOST" 'cd /tmp/sluice-pkg && sh install.sh'
```

`install.sh` 行为（对齐既有部署脚本的做法）：

1. 校验 root、`rc-service` 存在、二进制为静态链接（`ldd` 无 `=>`）。
2. 创建 `sluice` 系统用户与 `/var/lib/sluice`（0700）。
3. 安装二进制到 `/usr/local/bin`、initd 到 `/etc/init.d`、confd 到 `/etc/conf.d`。
4. 幂等：已存在的 `/etc/sluice/server.toml` 不覆盖（不重置 token）。
5. `rc-update add sluice default && rc-service sluice start`。

- 80 绑定：`sluice` 用户 + `capabilities="^cap_net_bind_service"`，无需 root。
- 云侧安全组需放行 **80 / 8443 / 7835**。
- 内存目标：常驻 RSS < 60 MB（总量 978 MB，余量约 485 MB）。

## 8. 性能验证

### 8.1 场景

| 编号 | 场景 | 用途 |
| --- | --- | --- |
| B1 | 本地直连本地服务 | 排除网络因素 |

### 8.2 指标与方法

| 指标 | 方法 |
| --- | --- |
| 延迟 | 1 KB 响应，顺序 200 次，取 p50/p95/p99 |
| 吞吐 | 1 MB / 10 MB，各 3 次取中位数 |
| TTFB | SSE 流首块到达时间 |
| 抖动 | SSE 块间隔标准差 |
| 资源 | `/proc/<pid>/status` 的 VmRSS、CPU time |
| 错误率 | 并发 8 / 32，统计非 2xx |

### 8.3 判定标准（按实测带宽校准）

- 吞吐 ≥ 0.42 MB/s（上行 446 KB/s 的 95%）；10 MB 响应物理下限 ≈22.5 s
- T1 相对 B2 额外延迟 ≤ 15 ms
- TTFB ≤ 直连 + 10 ms
- RSS：空闲 ≤ 30 MB，32 并发峰值 ≤ 80 MB
- 无雪崩：1×10 MB + 32×1 KB 并发时，小请求 p95 ≤ 基线 3 倍
- CPU：单核 < 70%（为既有服务留余量）

## 12. Git 流程

**首次推送**（M0 结束时执行一次）：

```bash
cd /Users/spencer/Documents/workspace/sluice
git init -b main
git add -A
git commit -m "chore: 初始化 sluice 工程骨架"
git remote add origin https://github.com/lfvepclr/sluice.git
git branch -M main
git push -u origin main
```

远端已确认为空仓库，首次推送不会冲突。若后续 `push` 被拒（远端已有提交），先 `git pull --rebase origin main`，**不要**直接 `--force`。

**日常提交**：每完成一个里程碑提交一次，粒度按功能点而非文件。

```bash
git add -A && git commit -m "feat(proto): 帧编解码与长度上限保护"
git push
```

**提交信息规范**（与既有仓库一致）：

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `feat(scope)` | 新功能 | `feat(server): 子域名分配与 60s 保留期` |
| `fix(scope)` | 修缺陷 | `fix(agent): 断线后子域名被误释放` |
| `test(scope)` | 只动测试 | `test(common): 补 path 解析边界用例` |
| `docs` | 只动文档 | `docs: 补 Alpine 部署与换域名步骤` |
| `chore` | 构建/依赖/杂项 | `chore: 升级 yamux 至 0.13` |

**分支策略**：个人项目，直接在 `main` 上按里程碑提交；每个里程碑结束打 tag（`v0.1.0-m1` …），便于回退与对比 benchmark 数据。

**不入库检查**（提交前跑一次）：

```bash
git status --porcelain | grep -E '(\.key|\.pem|\.env|server\.toml)$' && echo "STOP: 疑似密钥/本地配置"
```
