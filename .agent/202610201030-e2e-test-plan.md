## 目标

在进程内起完整链路（真实 TCP/TLS/yamux，无 mock），系统性验证两个方向的
端到端数据面，落成 `tests/e2e.rs` 常驻回归。已有的零散测试
（`ws_upgrade.rs`、`bench_smoke.rs`、`spike_yamux.rs`）只覆盖单点，
本计划补齐「一个测试文件跑通所有关键路径」。

## 链路定义

```
forward 方向（agent 开流 → server 出网）：
  本地调用方 → forward 代理 → [yamux 流: agent→server] → server SSRF 关卡 → 外网 target

expose 方向（server 开流 → agent 落地）：
  外部调用方 → ingress(HTTP/HTTPS) → [yamux 流: server→agent] → agent → 本地 target
```

两个方向共用同一条控制连接协议，但开流方向相反——这是「反过来也要成立」
的核心：`spike_yamux` 已在传输层验证双向开流，本计划在业务层整链验证。

## 实现要点

- 服务器用 `ServerHandle::start`（`:0` 随机端口）；HTTPS 入口开启，
  自签模式，客户端用接受任意证书的 rustls verifier（模拟 pin 语义）。
- 本地 target：测试内起 hyper 静态/回显服务（`/echo` POST 回显、`/1m` 1 MiB）。
- 大 payload 用 `Vec<u8>` 构造后整断言，1 MiB 量级不足以暴露缓冲问题但足以
  验证分块流式路径；更大数据量由 bench 覆盖。
- 保留期用例：主动 drop `ExposeSession`（mux 关闭 → 服务器标离线）后立刻请求。
- 验收：`cargo test --test e2e` 全绿；纳入 CI 常规 `cargo test`。
